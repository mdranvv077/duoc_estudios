Decisiones del laboratorio y equipos

Interpretamos 120, 60, 30 y 10 como clientes que deben poder recibir DHCP. Por eso el cálculo deja margen para las diez IP excluidas. La VLAN 100 se configura como nativa y de administración, tal como en la imagen; usa dos subredes porque sus sectores están separados por routers. Sus direcciones son estáticas, sin pool DHCP.

Los nombres Switch1–Switch4 se escriben SW1–SW4 en la CLI. Los cuatro multilayer se identifican MLS1–MLS4 según su posición en el plano. 02 · Configuración básica y SSH

Aplica esta base en cada router y switch. Cambia únicamente el hostname por MELIPILLA, ELMONTE, ISP, SW1–SW4 o MLS1–MLS4. El ejemplo comienza en Router>; los demás bloques parten del modo privilegiado.

Base común · routers y switches

Cisco IOS · CLIRouter · MELIPILLA
! BASE COMÚN · ROUTERS Y SWITCHES - MELIPILLA

enable
configure terminal
! IDENTIDAD
hostname MELIPILLA
banner motd #Acceso autorizado - Laboratorio DGNV#
ip domain-name dgnvstudios.cl

! CREDENCIALES DE PRACTICA
username soporte secret LabRedes26
enable secret AdminRedes26
service password-encryption

! CLAVES RSA
crypto key generate rsa
1024

! ACCESO SSH
ip ssh version 2
ip ssh authentication-retries 3
ip ssh time-out 120
line vty 0 4
login local
transport input ssh
exit

! CONSOLA
line console 0
password ConsolaRedes26
login
exit
end

Ver en la guía Configuración inicial · Configuración básica Configuración inicial · Seguridad del dispositivo Configuración inicial · Acceso por SSH
Notas de este bloque

1024 bits es el tamaño de clave usado en esta práctica y la respuesta al valor solicitado por IOS. Si ya existen claves, IOS puede pedir confirmar su sustitución: revisa ese paso antes de continuar. En equipos con VTY 5–15, aplica también login local y transport input ssh a ese rango. Las credenciales son ejemplos para esta práctica. SSH necesitará las IP y rutas de los bloques posteriores.

Detalles de esta etapa
