Módulo 02

BPDU, BID y elección.

Antes de bloquear un camino, los switches necesitan conversar para elegir un Root Switch y descubrir cuál es la mejor ruta hacia él.

Las BPDU son mensajes entre switches

Imagina que cada switch envía una pequeña ficha con información sobre sí mismo y sobre el camino que conoce. Esa ficha se llama BPDU, abreviatura de Bridge Protocol Data Unit.

Las BPDU no transportan los datos de los usuarios. Son mensajes de control que STP utiliza para comparar switches, elegir el Root Switch y decidir qué puertos pueden reenviar tráfico sin formar un bucle. Entre otros datos, informan el BID, el costo del camino y los temporizadores de STP.

El BID identifica a cada switch

El BID significa Bridge ID o identificador de puente. Es el valor que STP utiliza para identificar y comparar a los switches durante la elección del Root Switch. No es una dirección IP ni el nombre que escribimos con hostname; es una identidad propia de Spanning Tree.

Puedes imaginarlo como la cédula con la que cada switch se presenta ante los demás. El switch que posea el BID más bajo será elegido como Root Switch. En la salida de show spanning-tree aparece como Bridge ID para el switch actual y como Root ID para el switch que ganó la elección. El BID se construye con tres elementos:

  • Prioridad: es la primera parte que STP compara. Su valor base habitual es 32768, pero puede configurarse entre 0 y 61440. Un número menor tiene preferencia para convertirse en Root Switch.
  • ID de sistema extendido: identifica la instancia de STP. Cuando se utiliza PVST+, corresponde al número de la VLAN. Así, un mismo switch puede tener un BID diferente para la VLAN 10 y para la VLAN 20.
  • Dirección MAC: completa el BID e identifica al switch. Si varios switches tienen la misma prioridad dentro de la misma VLAN, gana el que posea la MAC numéricamente más baja.

Cómo se calcula la prioridad mostrada

El campo de prioridad del BID tiene 16 bits. Los primeros 4 se usan para la prioridad configurable y los otros 12 quedan reservados para el ID de sistema extendido. Como esos 12 bits están reservados, la prioridad base solo puede avanzar en bloques de 4096: 0, 4096, 8192, 12288 y así sucesivamente.

El valor que aparece en show spanning-tree se obtiene sumando la prioridad base y el número de VLAN. La dirección MAC forma la parte final del BID, pero no se suma como si fuera otro número de prioridad; se utiliza después para resolver un empate.

Ejemplo para la VLAN 10:
Prioridad predeterminada: 32768 + 10 = 32778.
Prioridad configurada en 4096: 4096 + 10 = 4106.
Como 4106 es menor que 32778, el switch configurado con 4096 tendrá preferencia en la elección del Root Switch.
Regla principal: gana el BID más bajo. Primero se compara la suma de prioridad e ID de sistema extendido. Si existe un empate, gana la dirección MAC más baja.

Priority y root no son lo mismo

Con priority escribes directamente el puntaje que deseas usar, por ejemplo 4096. Esto entrega un control exacto, pero debes conocer las prioridades de los otros switches.

En cambio, root primary es un atajo de Cisco: el switch revisa la topología e intenta ajustar su prioridad para convertirse en Root Switch. root secondary lo deja preparado como respaldo. Estos comandos no crean un tipo diferente de Root Switch; por debajo siguen trabajando con prioridades.

El costo representa la distancia

STP llama costo al valor que utiliza para comparar caminos. No se refiere a dinero ni a metros. Depende principalmente de la velocidad del enlace: un enlace más rápido suele tener un costo menor y, por lo tanto, resulta más conveniente.

  • 10 Mb/s: costo corto 100.
  • 100 Mb/s: costo corto 19.
  • 1 Gb/s: costo corto 4.
  • 10 Gb/s: costo corto 2.

Si un camino atraviesa varios enlaces, STP suma sus costos. Por ejemplo, dos enlaces FastEthernet tienen un costo total de 38. Un switch elegirá como Root Port el puerto que lo lleve al Root Switch con el menor costo acumulado.

Cómo se toman las decisiones

Puedes leer el proceso como una serie de preguntas. STP pasa a la siguiente solo cuando existe un empate:

  1. ¿Qué BPDU anuncia el Root BID más bajo?
  2. ¿Qué camino tiene el menor costo hasta el Root Switch?
  3. ¿Qué switch emisor tiene el BID más bajo?
  4. ¿Qué puerto emisor tiene el Port ID más bajo?

El resultado es una topología predecible: un Root Switch, un Root Port en cada switch que no sea raíz y un camino redundante que puede quedar en espera.
