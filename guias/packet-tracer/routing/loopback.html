Módulo 06

Interfaz Loopback.

Una Loopback es una interfaz virtual del router. Puedes asignarle una IP sin ocupar un puerto físico ni conectar otro cable. En este módulo verás cuándo sirve, cómo configurarla y qué significa realmente que permanezca activa.

Una dirección del router independiente de un puerto

Una interfaz física, como GigabitEthernet0/0, depende de su enlace: si se desconecta el cable, baja. La Loopback existe dentro del router y no depende de un enlace concreto. Por eso se usa como una dirección estable para identificar el equipo, administrarlo o probar su conectividad IP.

El número de Loopback0 solo identifica esa interfaz virtual; también podrías crear Loopback1. Cada una puede tener su propia IP. En el ejemplo usaremos 10.10.10.1/32: la máscara 255.255.255.255 representa una sola dirección, no una red de usuarios conectada a un puerto.

Distinción importante: que Loopback0 aparezca up/up indica que está activa dentro de R1. No garantiza que R2 pueda llegar a ella. Para alcanzarla desde otro equipo, debe existir un camino físico funcional y una ruta hacia su IP.

Ejemplo en Packet Tracer: R1 y R2

Conecta dos routers por GigabitEthernet0/0. El enlace entre ellos usa 10.0.0.0/30: R1 tiene 10.0.0.1 y R2 10.0.0.2. La Loopback 10.10.10.1/32 pertenece a R1. Los nombres de las interfaces pueden variar según el modelo elegido; usa las que realmente conectaste.

Primero configura el enlace y la Loopback en R1:

R1# configure terminal
R1(config)# interface gigabitEthernet 0/0
R1(config-if)# ip address 10.0.0.1 255.255.255.252
R1(config-if)# no shutdown
R1(config-if)# exit
R1(config)# interface loopback 0
R1(config-if)# ip address 10.10.10.1 255.255.255.255
R1(config-if)# no shutdown
R1(config-if)# end

interface loopback 0 crea o abre la interfaz virtual; ip address le asigna la dirección. no shutdown asegura que quede habilitada. No hay que configurar un switch ni un cable para la Loopback.

Hacerla alcanzable desde R2

R2 conoce directamente el enlace 10.0.0.0/30, pero aún no sabe dónde está 10.10.10.1. Configura su interfaz y una ruta estática hacia esa única dirección, con R1 como siguiente salto:

R2# configure terminal
R2(config)# interface gigabitEthernet 0/0
R2(config-if)# ip address 10.0.0.2 255.255.255.252
R2(config-if)# no shutdown
R2(config-if)# exit
R2(config)# ip route 10.10.10.1 255.255.255.255 10.0.0.1
R2(config)# end

La ruta dice: «para llegar a 10.10.10.1, entrega el paquete a 10.0.0.1». R1 puede responder porque 10.0.0.2 está en su red directamente conectada. En una red más grande, las rutas de ida y regreso deben existir en todos los tramos necesarios.

Comprobar el resultado

R1# show ip interface brief # Loopback0 debe figurar con 10.10.10.1 y up/up
R1# show interfaces loopback 0 # muestra los detalles de la interfaz virtual
R2# show ip route 10.10.10.1 # confirma la ruta hacia R1
R2# ping 10.10.10.1 # prueba el camino completo

Si el ping falla, comprueba primero que ambos puertos físicos estén activos, que las IP del enlace pertenezcan a la misma subred y que la ruta en R2 apunte a 10.0.0.1. Puede fallar el primer intento mientras se resuelve ARP; repite la prueba si el resto está correcto.

Prueba útil: si apagas GigabitEthernet0/0 de R1, su Loopback puede seguir mostrando up/up, pero R2 perderá el camino físico para alcanzarla. La Loopback no sustituye al enlace ni crea redundancia.

Relación con OSPF

OSPF necesita un router ID único. Una IP de Loopback puede servir como referencia estable para elegirlo, aunque también puedes definirlo explícitamente con router-id, como en el siguiente módulo. Crear la Loopback no activa OSPF ni anuncia su dirección automáticamente: eso requiere configurar el protocolo y las redes correspondientes.
