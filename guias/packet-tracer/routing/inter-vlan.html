Módulo 02

Routing inter-VLAN.

Puedes comunicar VLANs mediante subinterfaces de un router o mediante interfaces VLAN (SVI) de un switch capa 3.

Dos formas de comunicar las mismas VLANs

  • Switch capa 2 + router: el switch transporta las VLANs; las subinterfaces del router son sus gateways.
  • Switch capa 3: el propio switch tiene las gateways en sus SVI y enruta con ip routing.

Opción A · Switch capa 2 + router

El puerto del switch conectado al router debe ser trunk. En el router se crean subinterfaces: cada una recibe una etiqueta 802.1Q, una IP y se convierte en gateway de una VLAN. En este ejemplo: VLAN 10 usa 192.168.10.1, VLAN 20 usa 192.168.20.1 y VLAN 30 usa 192.168.30.1.

Configurar las subinterfaces

Router(config)# interface gigabitEthernet 0/0 # selecciona la interfaz física hacia el switch
Router(config-if)# no shutdown # habilita la interfaz principal
Router(config-if)# exit
Router(config)# interface gigabitEthernet 0/0.10 # crea la subinterfaz de VLAN 10
Router(config-subif)# encapsulation dot1Q 10 # asocia la subinterfaz a VLAN 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0 # define su gateway
Router(config-subif)# exit
Router(config)# interface gigabitEthernet 0/0.20 # crea la subinterfaz de VLAN 20
Router(config-subif)# encapsulation dot1Q 20 # asocia la subinterfaz a VLAN 20
Router(config-subif)# ip address 192.168.20.1 255.255.255.0 # define su gateway
Router(config-subif)# exit
Router(config)# interface gigabitEthernet 0/0.30 # crea la subinterfaz de VLAN 30
Router(config-subif)# encapsulation dot1Q 30 # asocia la subinterfaz a VLAN 30
Router(config-subif)# ip address 192.168.30.1 255.255.255.0 # define su gateway
Recuerda: el puerto del switch hacia este router debe ser trunk y permitir las VLANs 10, 20 y 30. La VLAN nativa 99 no necesita una subinterfaz si no tendrá tráfico de usuarios.

Opción B · Switch capa 3

Usamos las mismas VLANs 10, 20 y 30 y las mismas gateways, pero ahora viven en MLS1. No necesitas un router externo para comunicar estas VLANs ni subinterfaces con encapsulation dot1Q. Crear VLANs y configurar puertos access o trunk se hace igual que en capa 2; lo nuevo son las SVI y el enrutamiento.

ip routing se usa en configuración global para habilitar el enrutamiento del switch. no switchport se usa dentro de un puerto físico para convertirlo en puerto de capa 3 y poder asignarle una IP directamente. No son alternativas: un enlace enrutado normalmente utiliza ambos.

1. IP para cada VLAN: usar una SVI

Si el switch será la gateway de VLAN 10, 20 y 30, coloca las IP en interface vlan, no en sus puertos access o trunk. Aquí no se usa no switchport: esos puertos siguen transportando las VLANs en capa 2. 

MLS1(config)# ip routing # permite enrutar entre redes
MLS1(config)# vlan 10 # crea la VLAN si todavía no existe
MLS1(config-vlan)# exit
MLS1(config)# vlan 20
MLS1(config-vlan)# exit
MLS1(config)# vlan 30
MLS1(config-vlan)# exit
MLS1(config)# interface vlan 10 # selecciona la SVI de VLAN 10
MLS1(config-if)# ip address 192.168.10.1 255.255.255.0 # gateway de VLAN 10
MLS1(config-if)# no shutdown
MLS1(config-if)# exit
MLS1(config)# interface vlan 20
MLS1(config-if)# ip address 192.168.20.1 255.255.255.0 # gateway de VLAN 20
MLS1(config-if)# no shutdown
MLS1(config-if)# exit
MLS1(config)# interface vlan 30
MLS1(config-if)# ip address 192.168.30.1 255.255.255.0 # gateway de VLAN 30
MLS1(config-if)# no shutdown
MLS1(config-if)# exit
Para que la SVI esté up/up: la VLAN debe existir y tener al menos un puerto activo en estado forwarding que la transporte (access o trunk). Los PC usan la IP de su SVI como gateway. Este ejemplo reemplaza al router del caso anterior: no asignes la misma gateway al router y al switch simultáneamente.

VLAN no es lo mismo que SVI: vlan 10 crea la VLAN; interface vlan 10 configura su interfaz IP. Un switch capa 2 también puede tener una SVI para administración, pero eso no lo convierte en la gateway que enruta entre VLANs.

2. Puertos access y trunk: siguen siendo capa 2

Fa0/10 conecta un PC de VLAN 10; Fa0/20 y Fa0/30 conectan los de VLAN 20 y 30. Gi0/2 es un trunk hacia otro switch, si lo necesitas. Las VLANs ya quedaron creadas en el bloque anterior. No pongas IP en estos puertos ni uses no switchport. 

MLS1(config)# interface fastEthernet 0/10
MLS1(config-if)# switchport mode access
MLS1(config-if)# switchport access vlan 10
MLS1(config-if)# no shutdown
MLS1(config-if)# exit
MLS1(config)# interface fastEthernet 0/20
MLS1(config-if)# switchport mode access
MLS1(config-if)# switchport access vlan 20
MLS1(config-if)# no shutdown
MLS1(config-if)# exit
MLS1(config)# interface fastEthernet 0/30
MLS1(config-if)# switchport mode access
MLS1(config-if)# switchport access vlan 30
MLS1(config-if)# no shutdown
MLS1(config-if)# exit
MLS1(config)# interface gigabitEthernet 0/2
MLS1(config-if)# switchport trunk encapsulation dot1q # en modelos que permiten elegir encapsulación
MLS1(config-if)# switchport mode trunk
MLS1(config-if)# switchport trunk allowed vlan 10,20,30
MLS1(config-if)# no shutdown
MLS1(config-if)# exit

Configura también el otro extremo del trunk. Si tu modelo solo admite 802.1Q y no reconoce el comando de encapsulación, omite esa línea.

3. IP para un puerto físico: usar no switchport

Para un enlace enrutado hacia otro router o switch capa 3, la IP va directamente en el puerto. Por ejemplo, MLS1 usa 192.168.60.2/24 y el router del otro extremo usa 192.168.60.1/24. 

MLS1(config)# ip routing # habilita el enrutamiento del equipo
MLS1(config)# interface gigabitEthernet 0/1
MLS1(config-if)# no switchport # convierte este puerto en capa 3
MLS1(config-if)# ip address 192.168.60.2 255.255.255.0
MLS1(config-if)# no shutdown
MLS1(config-if)# exit

Ese puerto deja de ser access o trunk. Úsalo en un puerto disponible, no en el trunk que necesitas para las VLANs. Las SVI y los puertos enrutados pueden coexistir en el mismo switch. Para redes remotas, también necesitas rutas de ida y vuelta.

Comprobar las IP y las rutas

MLS1(config)# end
MLS1# show ip interface brief # revisa IP y estado de SVI y puertos
MLS1# show ip route # revisa las redes que puede alcanzar

Usa un modelo multilayer compatible, como el 3560 de Packet Tracer. ip routing no asigna IP ni convierte todos los puertos en capa 3; no switchport solo afecta al puerto seleccionado.
