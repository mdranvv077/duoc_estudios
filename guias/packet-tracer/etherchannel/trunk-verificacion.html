Módulo 04

Trunk, verificación y guardado.

Con los puertos físicos agrupados, configuraremos el trunk sobre Port-channel 1 y comprobaremos que ambos enlaces trabajan juntos.

Configurar la interfaz lógica

interface port-channel 1 abre la interfaz que representa al grupo completo. Desde aquí puedes aplicar una sola configuración de trunk para los dos enlaces físicos.

En este ejemplo pasarán las VLANs 10, 20, 30, 40 y 99. La VLAN 99 se usará como nativa únicamente para mantener la misma estructura de las prácticas anteriores; el número puede cambiar según el diseño de tu red. 

# aplica este bloque en SW1 y repítelo sin cambios en SW2
Switch(config)# interface port-channel 1 # entra a la interfaz lógica del grupo 1
Switch(config-if)# switchport mode trunk # convierte el Port-channel en trunk
Switch(config-if)# switchport trunk allowed vlan 10,20,30,40,99 # permite estas VLANs
Switch(config-if)# switchport trunk native vlan 99 # define la VLAN nativa del ejemplo
Switch(config-if)# switchport nonegotiate # evita negociar el trunk mediante DTP
Switch(config-if)# exit # vuelve a la configuración global
No confundas las negociaciones: switchport nonegotiate desactiva DTP, que negocia el modo trunk. No desactiva PAgP; el EtherChannel continúa usando PAgP para mantener agrupados los enlaces.

La configuración debe coincidir

Ambos extremos deben utilizar la misma VLAN nativa y la misma lista de VLANs permitidas. Si SW1 permite VLANs diferentes a SW2, el canal puede no formarse correctamente o transportar tráfico de manera inesperada.

Una vez creado el EtherChannel, realiza los cambios del trunk sobre Port-channel 1. Así el grupo mantiene una sola configuración lógica y no tienes que modificar Fa0/1 y Fa0/2 por separado.

Comprobar EtherChannel

Primero revisa el resumen. Después confirma que el Port-channel está funcionando como trunk y que PAgP reconoce al switch vecino. 

Switch# show etherchannel summary # muestra el grupo y sus puertos miembros
Switch# show interfaces port-channel 1 trunk # revisa VLAN nativa y VLANs permitidas
Switch# show pagp neighbor # comprueba el vecino que negoció mediante PAgP

En show etherchannel summary, busca Po1 y confirma que Fa0/1 y Fa0/2 aparezcan dentro del grupo. La letra P junto a cada puerto indica que está correctamente agrupado en el Port-channel.

Qué significan las letras del resumen

IOS utiliza letras cortas para mostrar el estado del Port-channel y de sus puertos. En esta práctica, el resultado esperado se parece a Po1(SU), con Fa0/1(P) y Fa0/2(P). Estas son las letras más útiles, ordenadas desde las más habituales hasta las menos comunes:

  • S — Layer 2: el Port-channel funciona en capa 2, como corresponde a este trunk entre switches.
  • U — En uso: el Port-channel está activo y puede transportar tráfico.
  • P — Dentro del Port-channel: el puerto físico se incorporó correctamente al grupo.
  • I — Independiente: el puerto quedó funcionando por separado y no se unió al canal.
  • s — Suspendido: el switch apartó el puerto porque detectó una incompatibilidad o un problema.
  • D — Apagado: el enlace o el Port-channel se encuentra caído.
  • R — Layer 3: el Port-channel funciona como una interfaz de capa 3, algo que no utilizamos en esta práctica.
  • H — En espera: enlace de respaldo utilizado por LACP; no debería aparecer en este ejercicio con PAgP.
  • u — No apto: el puerto no cumple las condiciones necesarias para unirse al grupo.
  • w — Esperando: el puerto todavía espera poder incorporarse al EtherChannel.
  • f — Fallo de asignación: el switch no pudo asociar el puerto al agregador lógico.
  • d — Puerto predeterminado: estado interno poco habitual en una práctica básica.
Las mayúsculas importan: S significa Layer 2, mientras que s significa suspendido. Asimismo, U indica que el canal está en uso, pero u señala que un puerto no es apto para agruparse.

Probar la redundancia

Cuando el canal esté funcionando, desconecta uno de los dos cables en Packet Tracer. El enlace restante debería conservar la comunicación. Al volver a conectar el cable, PAgP puede incorporarlo nuevamente al grupo. Esta prueba permite observar la utilidad del EtherChannel sin modificar la configuración.

Guardar al finalizar

Guarda la configuración en ambos switches después de comprobar que el grupo y el trunk funcionan correctamente. 

Switch(config)# end # regresa al modo privilegiado
Switch# copy running-config startup-config # guarda la configuración para el próximo inicio
