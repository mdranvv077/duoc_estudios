Módulo 03

HSRP con VLAN y subinterfaces.

Preparar una gateway virtual por VLAN y repartir los roles entre R1 y R2.

La misma idea, ahora una gateway por VLAN

En Router-on-a-Stick, cada subinterfaz del router atiende una VLAN. HSRP se configura dentro de cada subinterfaz: ambos routers participan en la VLAN 10 y ambos en la VLAN 20. Cada red tiene su propia IP virtual y su propio grupo.

R1 será Active de VLAN 10 y respaldo de VLAN 20; R2 hará lo contrario. Así ambos trabajan, pero cada grupo mantiene un único Active. No estamos repartiendo un mismo flujo entre los dos routers.

La base ya está preparada. Estos ejemplos parten de VLANs, trunks y subinterfaces con sus IP reales configuradas. Si necesitas preparar esa base, revisa Router-on-a-Stick. No mezcles este laboratorio con el grupo HSRP de la interfaz física del módulo anterior.

Por qué se configura así

Los dos routers deben coincidir en versión, grupo e IP virtual para cada VLAN. Usamos HSRP versión 2 y hacemos coincidir el grupo con la VLAN para facilitar la lectura.

La prioridad 110 deja a R1 como preferido de VLAN 10 y a R2 como preferido de VLAN 20; el respaldo usa 100. preempt permite que el router con mayor prioridad recupere el rol Active al volver. VLAN 99 no lleva HSRP en esta práctica.

PC10 y PC20

  • PC10: 192.168.10.10, máscara 255.255.255.0, gateway 192.168.10.1.
  • PC20: 192.168.20.10, máscara 255.255.255.0, gateway 192.168.20.1.

Primero prueba la gateway de cada PC; después, un ping de PC10 a 192.168.20.10. Las dos redes están directamente conectadas a ambos routers, así que esta comunicación inter-VLAN no necesita rutas estáticas adicionales.

Qué debe aparecer

Desde el modo privilegiado, comprueba los grupos en R1 y repite los mismos comandos en R2. show standby brief resume los roles y la IP virtual; show standby muestra el detalle de cada grupo.

En R1, grupo 10 Active y grupo 20 Standby; en R2, al revés. Si apagas R1, R2 debe poder atender ambas gateways. No cambias las IP de los PC. Si usas DHCP en otro ejercicio, entrega la IP virtual con default-router; HSRP no sincroniza pools ni hace redundante el servidor DHCP. El módulo 4 explica cómo preparar el respaldo de DHCP y otros servicios.

También existe en multilayer. En un switch capa 3 compatible, HSRP se configura sobre la SVI, por ejemplo interface vlan 10, con IP real propia y la misma IP virtual. Para enrutar entre VLANs necesita ip routing. No se configura sobre los puertos físicos de un EtherChannel de capa 2.
