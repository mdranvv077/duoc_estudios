Módulo 03

HSRP con VLAN y subinterfaces.

Preparar una gateway virtual por VLAN y repartir los roles entre R1 y R2.

La misma idea, ahora una gateway por VLAN

En Router-on-a-Stick, cada subinterfaz del router atiende una VLAN. HSRP se configura dentro de cada subinterfaz: ambos routers participan en la VLAN 10 y ambos en la VLAN 20. Cada red tiene su propia IP virtual y su propio grupo.

R1 será Active de VLAN 10 y respaldo de VLAN 20; R2 hará lo contrario. Así ambos trabajan, pero cada grupo mantiene un único Active. No estamos repartiendo un mismo flujo entre los dos routers.

La base ya está preparada. Estos ejemplos parten de VLANs y trunks preparados, con Gi0/1 de R1 y Gi0/2 de R2 activas y sin IP en la interfaz física. Los bloques configuran sus subinterfaces y HSRP. Si necesitas preparar esa base, revisa Router-on-a-Stick. No mezcles este laboratorio con el grupo HSRP de la interfaz física del módulo anterior.

Red general: 172.16.0.0/20. De ella usamos dos subredes /25, ambas con máscara 255.255.255.128. La gateway virtual y las IP reales de cada grupo pertenecen a su misma subred.

HSRP en cada router

Parte desde el modo de configuración global de cada router. Incluimos únicamente las subinterfaces, sus IP y HSRP; no repetimos hostname ni la configuración general. encapsulation dot1Q identifica la VLAN de cada subinterfaz. Si ya estaba configurada, repetirla no cambia esa asociación.

R1 · Active preferido de VLAN 10

Cisco IOS · CLIRouter · R1
! VLAN 10 · Active preferido
interface gigabitEthernet 0/1.10
encapsulation dot1Q 10
ip address 172.16.0.2 255.255.255.128
standby version 2
standby 10 ip 172.16.0.1
standby 10 priority 120
standby 10 preempt
exit
! VLAN 20 · Standby preferido
interface gigabitEthernet 0/1.20
encapsulation dot1Q 20
ip address 172.16.0.130 255.255.255.128
standby version 2
standby 20 ip 172.16.0.129
standby 20 priority 80
standby 20 preempt
exit

Por qué se configura así

Los dos routers deben coincidir en versión, grupo e IP virtual para cada VLAN. Usamos HSRP versión 2 y hacemos coincidir el grupo con la VLAN para facilitar la lectura.

La prioridad 120 deja a R1 como preferido de VLAN 10 y a R2 como preferido de VLAN 20; el respaldo usa 80. preempt permite que el router con mayor prioridad recupere el rol Active al volver. VLAN 99 no lleva HSRP en esta práctica.

PC10 y PC20

  • PC10: 172.16.0.10, máscara 255.255.255.128, gateway 172.16.0.1.
  • PC20: 172.16.0.140, máscara 255.255.255.128, gateway 172.16.0.129.

Primero prueba la gateway de cada PC; después, un ping de PC10 a 172.16.0.140. Las dos redes están directamente conectadas a ambos routers, así que esta comunicación inter-VLAN no necesita rutas estáticas adicionales.

Qué debe aparecer

Desde el modo privilegiado, comprueba los grupos en R1 y repite los mismos comandos en R2. show standby brief resume los roles y la IP virtual; show standby muestra el detalle de cada grupo.

Cisco IOS · CLIRouter · R1 / R2
show standby brief
show standby

En R1, grupo 10 Active y grupo 20 Standby; en R2, al revés. Si apagas R1, R2 debe poder atender ambas gateways. No cambias las IP de los PC. Si usas DHCP en otro ejercicio, entrega la IP virtual con default-router; HSRP no sincroniza pools ni hace redundante el servidor DHCP. El módulo 4 explica cómo preparar el respaldo de DHCP y otros servicios.

También existe en multilayer. En un switch capa 3 compatible, HSRP se configura sobre la SVI, por ejemplo interface vlan 10, con IP real propia y la misma IP virtual. Para enrutar entre VLANs necesita ip routing. No se configura sobre los puertos físicos de un EtherChannel de capa 2.
