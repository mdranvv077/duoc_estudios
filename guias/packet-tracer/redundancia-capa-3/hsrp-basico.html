Módulo 02

HSRP sin VLAN.

Configurar una gateway compartida con dos routers, un switch y un PC.

Un primer laboratorio sin trunks ni subinterfaces

Empieza con equipos nuevos o una copia limpia del archivo. Conecta R1 Gi0/0 a SW1 Gi0/1, R2 Gi0/0 a SW1 Gi0/2 y PC10 Fa0 a SW1 Fa0/10, con cable de cobre directo. No hace falta conectar los routers directamente entre sí: hablan a través del switch.

Una sola LAN. Los tres puertos del switch pertenecen a la VLAN 1 predeterminada. Aquí «sin VLAN» significa sin segmentación ni trunks, no que el switch deje de utilizar VLANs.
ElementoDirección / máscaraUso
R1 · Gi0/0192.168.10.2 /24IP propia del primer router.
R2 · Gi0/0192.168.10.3 /24IP propia del respaldo.
Grupo HSRP 10192.168.10.1Gateway virtual compartida.
PC10192.168.10.10 /24Gateway 192.168.10.1.

Preparar SW1

Los tres puertos van en access y en la misma VLAN 1. No creamos segmentación en este ejercicio. PortFast se aplica solo al puerto del PC.

Cisco IOS · CLISwitch · SW1
enable
configure terminal
hostname SW1
interface range gigabitEthernet 0/1-2
switchport mode access
switchport access vlan 1
no shutdown
exit
interface fastEthernet 0/10
switchport mode access
switchport access vlan 1
spanning-tree portfast
no shutdown
end
copy running-config startup-config

R1: el que preferimos como Active

Ejecuta el bloque en R1. La IP real se configura con ip address; la virtual, con standby 10 ip. No las intercambies.

Cisco IOS · CLIRouter · R1
enable
configure terminal
hostname R1
interface gigabitEthernet 0/0
ip address 192.168.10.2 255.255.255.0
standby 10 ip 192.168.10.1
standby 10 priority 110
standby 10 preempt
no shutdown
end
copy running-config startup-config

R2: el respaldo preparado

R2 usa la misma IP virtual y el mismo grupo, pero otra IP real y una prioridad menor.

Cisco IOS · CLIRouter · R2
enable
configure terminal
hostname R2
interface gigabitEthernet 0/0
ip address 192.168.10.3 255.255.255.0
standby 10 ip 192.168.10.1
standby 10 priority 100
standby 10 preempt
no shutdown
end
copy running-config startup-config

Los cuatro comandos que hay que entender

En estos equipos partimos de la versión predeterminada HSRPv1; los grupos 10 y 20 están dentro de su rango. HSRPv2 también existe, pero no necesitas cambiar de versión para esta práctica. Lo importante es no mezclar versiones entre participantes del mismo grupo.

ComandoQué significa
standby 10 ip 192.168.10.1Participar en el grupo 10 con esa gateway virtual.
standby 10 priority 110Preferir a este equipo: gana la prioridad mayor.
standby 10 preemptPermitir que tome el rol Active si tiene mayor prioridad que el Active actual.
show standby briefVer grupo, prioridad, estado, Active, Standby e IP virtual.

La prioridad predeterminada es 100. Si hay empate durante la elección, interviene la IP real más alta; usamos 110 y 100 para que la intención sea clara. Preempt no es lo que permite sustituir a un router que desapareció: sirve para tomar el mando cuando el Active sigue presente, pero tiene menor prioridad, como al volver R1 después de una falla.

Preparar el PC y confirmar

En PC10 → Desktop → IP Configuration, selecciona Static: IP 192.168.10.10, máscara 255.255.255.0 y gateway 192.168.10.1. No necesitas DNS para probar por IP.

Cisco IOS · CLIRouter · R1
show ip interface brief
show standby brief
show standby

Repite las verificaciones en R2. Una vez convergido, R1 debe quedar Active y R2 Standby. Desde la terminal del PC, prueba ping 192.168.10.1. Un primer ping puede perderse mientras se resuelve ARP; repítelo antes de concluir que hay una falla.

La prueba tiene un límite. Con esta topología puedes comprobar la disponibilidad de la gateway, pero no el acceso a una red remota. Eso requeriría añadir una red de destino y rutas de ida y vuelta en ambos routers.
