Módulo 02 · Seguridad de capa 2

Cada puerto tiene una función.

Primero dejaremos una LAN que funcione. Después cerraremos los puertos que no necesitamos, sin cortar los enlaces útiles.

Preparar la red antes de aplicar Port Security

Trabaja con un 2960 nuevo. PC1 va a Fa0/18 y PC2 a Fa0/19. Ambos tendrán un puerto access en VLAN 10. Crear la VLAN y asignar los puertos evita depender de una configuración anterior que no conocemos.

IOS · CLISwitch · SW1 · LAN base
enable
configure terminal
hostname SW1
vlan 10
name USUARIOS
exit
vlan 999
name SIN_USO
exit
interface fastEthernet 0/18
description PC1
switchport mode access
switchport access vlan 10
no shutdown
exit
interface fastEthernet 0/19
description PC2
switchport mode access
switchport access vlan 10
no shutdown
end

Configura PC1 con 192.168.10.11 /24 y PC2 con 192.168.10.12 /24. Desde Command Prompt de PC1 ejecuta ping 192.168.10.12. Repite si el primer intento pierde una respuesta mientras se resuelve ARP. Debe funcionar antes de añadir protección.

Puertos sin uso: aislados y apagados

En esta topología solo se usan Fa0/18 y Fa0/19. Los demás puertos pueden quedar en una VLAN de aparcamiento y en shutdown. La VLAN 999 facilita reconocerlos, pero el apagado administrativo es lo que impide que una conexión nueva use ese puerto.

IOS · CLISwitch · SW1 · Puertos sin uso
configure terminal
interface range fastEthernet 0/1-17
description SIN_USO
switchport mode access
switchport access vlan 999
shutdown
exit
interface range fastEthernet 0/20-24
description SIN_USO
switchport mode access
switchport access vlan 999
shutdown
exit
interface range gigabitEthernet 0/1-2
description SIN_USO
switchport mode access
switchport access vlan 999
shutdown
end

Este rango pertenece a nuestro laboratorio. Si tu switch ya tiene un uplink, un trunk o un EtherChannel en alguno de esos puertos, exclúyelo. Un puerto sin tráfico en este momento no necesariamente es un puerto sin uso.

Los puertos de PC y las BPDU

Este complemento conecta con la categoría de Spanning Tree. PortFast permite que el puerto del PC pase rápidamente a forwarding. BPDU Guard lo deshabilita si recibe una BPDU, porque esperamos un equipo final, no otro switch participando en STP.

IOS · CLISwitch · SW1 · Puertos de equipos finales
configure terminal
interface range fastEthernet 0/18-19
spanning-tree portfast
spanning-tree bpduguard enable
end

Aplica estos comandos a los puertos de los PCs. No copies esta política sobre trunks o enlaces normales entre switches. PortFast no desactiva STP y BPDU Guard no reemplaza Port Security: una medida vigila BPDUs y la otra controla MAC de origen.

¿Y si después agregamos otro switch?

Ese enlace necesitará su propia configuración: modo trunk explícito, VLANs permitidas necesarias y VLAN nativa coherente en ambos extremos. No lo mezcles con los puertos de usuarios ni le apliques el límite de una MAC pensado para un PC. Puedes repasar el módulo de trunk estático cuando amplíes la topología.

Comprobar y guardar la copia base

IOS · CLISwitch · SW1 · Verificación de la base
show vlan brief
show interfaces status
show interfaces fastEthernet 0/18 switchport
show running-config
copy running-config startup-config

Fa0/18 y Fa0/19 deben estar en VLAN 10 y conectados. Los puertos que apagaste deben aparecer administrativamente deshabilitados. Revisa también que las protecciones de STP estén en los dos puertos de PC. En salidas largas, avanza con Espacio si aparece --More--. Al guardar, acepta con Enter el nombre de destino si te lo solicita.

Guarda una copia del archivo .pkt. Llámala, por ejemplo, seguridad-l2-base.pkt. Esa copia tiene conectividad y preparación de puertos, pero todavía no tiene Port Security. Será el punto de partida de cada alternativa.

Hasta aquí, cualquier PC conectado a Fa0/18 podría enviar tráfico. En el siguiente módulo veremos cómo cambia eso cuando el puerto solo admite una MAC segura.
