Lección 05

Acceso remoto por SSH.

SSH permite administrar un dispositivo desde otra red mediante una conexión cifrada, en lugar de exponer las credenciales en texto plano.

SSH frente a Telnet: Telnet permite una administración remota parecida, pero no cifra usuario, contraseña ni comandos. Por eso es una mala práctica en redes reales; SSH protege esa información mediante cifrado.

Antes de activar SSH

Para que SSH funcione, IOS necesita un nombre de dominio y claves RSA. También requiere un usuario local, que ya creaste en la sección anterior. Las líneas VTY son las puertas virtuales que reciben las conexiones remotas.

La configuración de SSH no asigna aún una dirección IP al router. Eso se hará más adelante; por ahora deja preparado el método de acceso seguro.

Habilitar el acceso seguro

Router(config)# ip domain-name guia-lab.local # define el dominio usado por las claves
Router(config)# crypto key generate rsa modulus 1024 # genera las claves RSA para SSH
Router(config)# ip ssh version 2 # selecciona la versión segura de SSH
Router(config)# line vty 0 4 # abre las líneas de acceso remoto
Router(config-line)# login local # usa el usuario local creado
Router(config-line)# transport input ssh # permite solo conexiones SSH
Resultado esperado: el equipo acepta SSH cuando tenga conectividad IP, y rechaza Telnet en las líneas VTY configuradas.
