¿Aparece ese valor en la sucesión?

Buscar pertenencia significa encontrar una posición entera válida. El while del formulario funciona solo cuando su condición de parada tiene sentido.

Ahora conocemos el valor, no la posición

En el problema 2 queremos saber si 54870 pertenece a aₙ = n³ − 2. No estamos pidiendo a₅₄₈₇₀. Buscamos una posición n para la que n³ − 2 = 54870.

Esta sucesión es estrictamente creciente para las posiciones n ≥ 1 y sigue creciendo sin cota superior. Podemos avanzar mientras el término sea menor que el objetivo. Al terminar, lo habremos alcanzado o superado.

Adaptar la segunda plantilla

Mantenemos dif = final - termino del formulario, pero comenzamos evaluando el primer término real. Así no confundimos el valor inicial cero con un término ni omitimos el primer término negativo.

Python · Buscar 54870
final = 54870
n = 1
termino = n**3 - 2
dif = final - termino

while dif > 0:
    n += 1
    termino = n**3 - 2
    dif = final - termino

if dif == 0:
    print(f'El {final} es un término y ocupa el lugar {n}')
else:
    print(f'El {final} no pertenece a la sucesión')

Resultado esperado
El 54870 es un término y ocupa el lugar 38
Valor de difInterpretaciónAcción
Mayor que 0El término todavía es menor que el objetivo.Avanzar a la siguiente posición.
Igual a 0El término coincide con el objetivo.Informar que pertenece y dar n.
Menor que 0Ya se superó el objetivo.En una sucesión creciente, los siguientes no volverán a él.

Por ejemplo, a₃₇ = 50651 y a₃₈ = 54870. La diferencia llega a cero en n = 38. Si cambias el objetivo a 54871, el siguiente término es 59317: lo supera y podemos concluir que 54871 no pertenece.

Actualizar es obligatorio. Dentro del while deben cambiar n, termino y dif. Si olvidas actualizar la condición, puedes dejar un ciclo infinito. En Colab puedes detener una celda con el botón de interrupción.

Por qué no sirve para cualquier regla

bₙ = (8 − n)² comienza 49, 36, 25, 16, 9, 4, 1, 0 y después vuelve a crecer. Si buscas 9 con el criterio «parar cuando se supera», el primer término 49 ya lo supera y se podría rechazar incorrectamente. Sin embargo, b₅ = 9 y b₁₁ = 9.

El problema 4 busca 290. El código del archivo llega a un «no» correcto para ese objetivo, pero eso no vuelve general el procedimiento. Hay que entender la forma de la sucesión antes de reutilizarlo.

Una búsqueda acotada para reglas no monótonas

Para buscar sin asumir crecimiento, definiremos un intervalo: las posiciones 1 a 30. Evaluamos todas y guardamos las coincidencias. Es una adaptación del while, con un límite que garantiza que termina.

Python · Buscar todas las posiciones de 9
final = 9
limite = 30
n = 0
posiciones = []

while n < limite:
    n += 1
    termino = (8 - n)**2
    if termino == final:
        posiciones.append(n)

if len(posiciones) > 0:
    print(f'El {final} aparece en las posiciones {posiciones}')
else:
    print(f'El {final} no aparece entre 1 y {limite}')

Resultado esperado
El 9 aparece en las posiciones [5, 11]

El límite 30 es una decisión de esta búsqueda. Si no encontramos un valor, solo sabemos que no apareció en esas treinta posiciones. No podemos convertir esa ausencia en «no pertenece nunca» sin una justificación matemática adicional.

Justificar el caso 290

Como 8 − n es entero, su cuadrado debe ser un cuadrado perfecto no negativo. Tenemos 17² = 289 < 290 < 324 = 18². Por tanto, 290 no es un cuadrado de un entero y no pertenece a bₙ. Esa explicación sí cubre toda la sucesión.

Enteros y decimales

En estos problemas comparamos valores enteros calculados con potencias enteras, por lo que == es adecuado. Con otros decimales puede haber pequeños errores de representación. Una comparación con tolerancia puede servir para aproximaciones, pero no convierte una coincidencia aproximada en pertenencia matemática exacta.

For o while en este episodio

For con range es cómodo cuando ya sabemos cuántas posiciones recorrer. While repite mientras una condición siga siendo verdadera: no conoce automáticamente cuándo conviene parar. Hay que diseñar esa condición y comprobar sus límites.
