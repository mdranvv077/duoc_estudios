Módulo 05

Ejecutar, comprobar e interpretar.

Python puede entregar un resultado correcto para el código escrito y, aun así, ese resultado puede no responder correctamente el problema.

Tres comprobaciones diferentes

  1. El código se ejecuta: no aparecen errores de escritura, nombres o librerías.
  2. El cálculo corresponde: la fórmula y los datos son los del ejercicio.
  3. La respuesta tiene sentido: pertenece al contexto y utiliza las unidades adecuadas.

Superar la primera comprobación no garantiza las otras dos. Python ejecutará exactamente lo que escribiste, incluso si copiaste un dato equivocado.

Prueba con un valor sencillo

Antes de utilizar una tabla grande o generar un gráfico, prueba la función con una entrada cuyo resultado puedas calcular a mano. Si ambas respuestas coinciden, tienes una primera señal de que la adaptación está bien hecha.

def modelo(x):
    return 2 * x + 3

print(modelo(0))
Python · resultado3

Interpretar no es repetir el número

Si el resultado es 3, todavía falta saber qué representa. Una interpretación completa nombra la variable, añade la unidad y relaciona el resultado con la entrada utilizada.

Ejemplo de redacción: “Cuando la entrada es 0 unidades, el modelo entrega un valor inicial de 3 unidades”. Más adelante reemplazaremos “unidades” por meses, centímetros, gigabytes, segundos u otra medida del problema.

Revisa el contexto

Una solución matemática puede ser negativa, decimal o muy grande. Eso no significa automáticamente que sirva como respuesta. Si la variable representa personas, por ejemplo, normalmente no tendría sentido responder 4,7 personas; y si representa tiempo transcurrido, un valor negativo podría quedar fuera de la situación estudiada.

  • Comprueba las unidades.
  • Revisa si el valor está dentro del periodo o rango solicitado.
  • Decide si la variable puede aceptar decimales.
  • Explica cualquier aproximación o redondeo.

Cuando algo falla

Lee primero la última línea del mensaje de error, confirma que ejecutaste las importaciones y revisa la celda modificada. Evita cambiar varias partes al azar: corrige una causa posible, vuelve a ejecutar y observa qué cambió.
